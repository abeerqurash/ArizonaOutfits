WHAT IS CONNECTED
- New orders, payment/status/tracking changes, archived/restored orders.
- Low/out-of-stock alerts, resolved alerts and recorded inventory movements.
  Reports, valuation and reorder dashboard use these underlying inventory events.
- Customer registration/detail/status changes and deletion.
- New reviews, moderation and deletion.
- Successful admin edits for products, categories, tags, coupons, blog posts and
  blog categories, Store Settings, CMS, Menu Builder, Admin Team, roles, email
  templates, purchase orders and suppliers, through existing audit middleware.
- Backup completion/failure, including service-driven backups.
- Existing manual Notification Center messages continue to work.
- Global analytics and audit-log browsing do not create alerts; order/change
  events cover the underlying activity. Reading alerts never creates more alerts.

RECIPIENTS AND DISPLAY
Super admins receive all connected events. Staff require BOTH the relevant menu
permission and notifications.manage. Disabled admins are excluded.
The dropdown still shows the latest six; View all shows the full list.
Refresh the page to fetch new alerts. This package does not add live polling.
Only future recorded events are notified; existing historical orders/stock alerts
are not imported into the bell. A stock alert already active before installation
will notify on a subsequent state change, not every repeated scan.
No bell notification sends SMS or email; existing email flows remain separate.
Direct SQL/bulk query updates that bypass model events and admin audit middleware
do not generate alerts. Successful edits need the existing admin.audit middleware.
