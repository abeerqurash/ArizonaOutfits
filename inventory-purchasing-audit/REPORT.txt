1. INVENTORY ALERTS
PASS: Low-stock creation, repeated-check deduplication and transition from low
stock to out of stock work. Repeated checks did not send duplicate fake emails.
PROBLEM: Alerts use config('inventory.low_stock_threshold') while reorder uses
each product/variant reorder_point. Stock 8 with reorder point 10 needs reorder,
but creates no alert when the global threshold is 5.
PROBLEM: Purchase-order receiving updates stock without synchronizing alerts.
A fixture was replenished from stock 2 to 6 while its active low-stock alert
remained active. Both alert status and displayed stock can become stale.
Repair: define one threshold policy and apply it consistently to alerts, reports,
valuation and reorder. Synchronize affected product/variant alerts after committed
receipts, corrections and supplier returns, as well as ordinary stock movements.

CONNECTED INVENTORY ADJUSTMENT BLOCKER
InventoryAdjustmentService requires App\Models\User, but an authenticated admin
is App\Models\Admin. The real service call reproduced a TypeError before stock
could change. The controller catches it and returns the error. InventoryHistoryService
also types its user actor as User. Fix actor handling throughout this call chain
and keep admin_id/user_id distinct. Add business validation for stock removal
against available quantity; the service currently calculates before - quantity
without a stock-floor guard (database behavior may reject negative values).

6. PURCHASE ORDERS, RECEIVING, CORRECTIONS AND RETURNS
PASS: Purchase creation stores the actual admin creator, takes supplier snapshots
and honors assigned supplier unit prices and minimum order quantities.
Blocked/inactive suppliers cannot receive new purchase orders.
PASS: After the actor FK blocker was isolated, tracked receipts incremented stock
and created receipt rows. Over-receiving, foreign PO lines and draft receiving
were rejected. Full receipt status, correction quantity limits, return stock
deduction, cancellation restoration, repeat-cancel rejection and completed-return
credit handling worked in the isolated scenarios.
HIGH: Receipt received_by and supplier-return created_by/completed_by/cancelled_by
still reference users, while the handlers write admin IDs. Actual local foreign
keys confirm it. With admin 99 and no user 99 the receipt failed and rolled back.
With unrelated user 99 present, receipt receiver became that customer.
MEDIUM: Creation accepts duplicate product/variant identifiers and creates multiple
identical lines. The draft update endpoint correctly requires distinct identifiers,
so creating and editing the same PO follow different rules.
MEDIUM: markOrdered checks an in-memory model, then saves without locking/rechecking
the persisted state. A stale draft instance downgraded a partially received PO
to ordered. This was a stale-object simulation, not a MariaDB concurrency test.
MEDIUM: Draft optimistic locking compares updated_at timestamps at second precision.
Two saves in the same second accepted the same old version; the second stale
submission overwrote the first. Use a monotonic version/adequate precision with
an atomic comparison, not merely a seconds timestamp.
Receipts also need the alert synchronization described in section 1.

All seven modules permit an authenticated active admin without checking the
existing inventory.manage / purchase-orders.manage / suppliers.manage permissions.
Each fixture restricted admin received response 200 where its module required 403.
Extend the new middleware and sidebar checks to these modules and nested actions.
Do not rely only on hiding links. Product inventory adjustments need an explicit
inventory permission policy rather than accidental classification by products.*.

SHARED CURRENCY GAP - MEDIUM
Suppliers support GBP, USD, EUR, PKR, AED and CNY. Purchase rows, summaries and
several Excel formats hard-code pounds. A fixture USD order of 100 rendered
as GBP 100. Purchase/supplier aggregate queries sum differing currencies without
grouping or conversion. Present per-currency totals or use an explicitly stored
base-currency conversion policy. Align inventory labels with the chosen catalog
currency; changing the symbol alone does not convert amounts.

LIMITATIONS AND DELIVERY
This is a read-only audit of the installed application plus isolated fixture
execution. It does not prove MariaDB concurrent writes, actual mail/queue delivery,
browser JavaScript interactions or PDF/XLSX binary/layout output. CSV output and
Excel calculation code were exercised. Supplier email jobs were faked, not sent.
The uploaded fixture document is under this audit's _checks/files directory;
no real supplier uploads or storage files were changed.
This REPORT.txt is a report, not replacement PHP code. The next repair set needs
complete PHP/Blade TXT files plus a non-destructive migration, because actor
relationships and ratings cannot be fully repaired with controller files alone.
