ADMIN DASHBOARD SIDEBAR AUDIT - 1 OCTOBER 2026

SUMMARY
32 link/action occurrences checked; all 32 resolve to registered routes.
The brand and Dashboard menu share a destination. The audit includes
View Website and the POST Logout form. There are 29 distinct admin GET
navigation destinations, all checked for active-state rendering.
No application source or live database records were changed.

WHAT PASSED
- Every sidebar named route exists and accepts its intended HTTP method.
- Generated URLs match their intended route; no sidebar route shadowing found.
- Controller classes and public action methods exist.
- Literal view destinations referenced by those actions exist.
- All nine permission-based administration links render for a super admin.
- Those nine links hide when the synthetic admin has no matching permissions.
- Content permission shows CMS Pages and Menu Builder without Admin Team.
- Coexisting customer and administrator fixture sessions use the admin guard
  when auth:admin selects that guard, as Laravel does for real admin requests.
- Logout uses POST with the Blade CSRF directive. It was not submitted.
- The sidebar JavaScript includes mobile link-click, overlay, close-button,
  and resize handling. These handlers were reviewed, not tested in a live browser.

CONFIRMED ISSUES

1. Archived Orders highlights two menus.
Orders matches admin.orders.* and therefore also matches admin.orders.archived.
Rendering the archive destination confirms both Orders and Archived Orders
receive the active class. All other 28 distinct admin destinations highlight
one expected navigation link.
File: C:\xampp\htdocs\ArizonaOutfits\resources\views\admin\partials\sidebar.blade.php

2. Reorder badge composer targets an unused sidebar view.
The admin layout includes admin.partials.sidebar. AppServiceProvider registers
the reorderRequiredCount composer for admin.layouts.sidebar instead.
Consequently the actual sidebar does not receive that count from this composer.
Its fallback zero hides the badge even when qualifying inventory exists.
File: C:\xampp\htdocs\ArizonaOutfits\app\Providers\AppServiceProvider.php
Layout: C:\xampp\htdocs\ArizonaOutfits\resources\views\admin\layouts\app.blade.php

3. Inventory Alerts badge composer is in a controller boot() method.
InventoryAlertController::boot() registers activeInventoryAlertCount, but
Laravel does not automatically call controller boot methods. No invocation
was found. The actual sidebar defaults the missing count to zero.
Both inventory/reorder badges rendered correctly when fixture counts were
provided, confirming the problem is data wiring rather than badge markup.
File: C:\xampp\htdocs\ArizonaOutfits\app\Http\Controllers\Admin\InventoryAlertController.php

4. Permission-hidden menus do not guarantee protected destinations.
The administration-links partial checks permissions to hide links. Several
linked destinations, including Roles & Permissions and Backups, do not
enforce those permission slugs in route middleware or their controller.
They use authentication/active-admin checks, which are not role permissions.
A missing menu link alone does not prevent direct URL access by another
active administrator. This should be fixed at the server before relying on
restricted administrator roles. Existing main sidebar links are generally
always shown; do not assume every module already applies role permissions.

LIMITS

database. Controllers and full pages were not executed with real accounts,
and logout/export/backup/payment actions were not performed. Some pages may
still have database, service, or full-layout runtime errors.
The JSON files retain the route map and rendered active-state evidence.
