ARIZONAOUTFITS COMPLETE ADMIN + CUSTOMER SYNC SET
54 separate replacement text files. No ZIP.
Prepared 3 October 2026. The installed application has NOT been changed.

INSTALLATION
1. Make a copy of your ArizonaOutfits project folder and back up your database.
2. Stop php artisan serve while replacing files.
3. Open each numbered .txt file and copy ALL its contents.
4. Open its destination below, replace ALL contents, and save.
   If the destination file does not exist, create it in the listed folder.
   Save real PHP files as .php and Blade files as .blade.php, not .txt.
5. Install ALL 54 files together, including the new AdminAccessPolicy service.
   Files 01-51 repeat the complete prepared admin set, with CheckoutController
   updated for archived customer confirmations. Files 52-54 fix customer accounts.
6. No new database migration is included in this package. Keep the migrations
   already supplied in the earlier inventory/customer phases installed.

Run these commands in a terminal opened in C:\xampp\htdocs\ArizonaOutfits:
C:\xampp\php\php.exe artisan optimize:clear
C:\xampp\php\php.exe artisan serve

Then refresh your browser with Ctrl+F5.

IMPORTANT CUSTOMER TESTS
- Change email through Login & Security, open the verification email, sign out,
  and confirm the new address logs in. The old address must stop logging in.
- Change password through profile and through Login & Security. Both must reject
  the current and immediately previous password.
- Account deletion must refuse users with current OR archived orders.
- A disposable customer without orders can delete their account; a simultaneous
  admin login in that browser must remain active.
- Archived order detail, invoice and authorized confirmation must open.

ADMIN CHECKS AFTER INSTALLATION
Recheck Store Settings, CMS Pages, Menu Builder, Global Analytics, Admin Team,
Roles & Permissions, Notification Center, Audit Logs, Backups, Email Templates,
Customers, Reviews, Blog Posts, Blog Categories and inventory/purchasing menus.
Also recheck your existing customer orders, archived orders, payment verification,
products, product categories/tags and coupons with normal fixture data.
Automated regressions cover shared settings/order/stock behavior and previous
admin/content/inventory modules; they do not replace all browser acceptance tests.

Live Stripe, Google/Facebook delivery and SMS are not certified by these tests.
Phone verification remains local development only until an SMS provider is added.
